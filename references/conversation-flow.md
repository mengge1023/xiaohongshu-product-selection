# 对话流程

## 状态

单品字段：`url, sales_total, cart_24h, benchmarks[], sale_price, purchase_price, shipping_cost, material_level`。每条 benchmark 包含 `followers, days_ago, likes, same_product`。

按字段顺序处理，但先吸收用户主动提供的所有明确值，并先调用 WorkBuddy 可用能力自动补齐。一次只询问一个自动抓取后仍缺失的最靠前字段。模糊值必须确认；用户纠正时覆盖旧值并重新校验。

1. 从商品页抓取累计销量；>11000 立即换品。抓不到才问。
2. 从商品页抓取 24h 加购；<200 立即换品。抓不到才问。
3. 自动搜索并读取同款对标。单条对标的粉丝、发布时间、点赞、同款确认和 URL 必须绑定；允许添加多条，绝不跨笔记拼接。
4. 从小红书商品页读取售价；从用户提供的 1688/阿里巴巴链接读取对应规格的拿货价和单件运费。缺货源链接时只询问链接；调用利润脚本。
5. 根据真实抓取的素材证据评级 A/B/C；证据不足才追问，不接受“挺多”等模糊描述。
6. 数据齐全后调用校验/评分脚本并报告。

## URL

不要仅凭域名猜产品页或笔记页。用 WorkBuddy 页面读取能力确认页面类型与可见内容；笔记页优先自动提取关联商品，提取不到才请用户补充商品链接。

## AB

维护 `product_a`、`product_b` 两套状态。默认完整处理 A 后再处理 B。某方硬淘汰即停止该方，继续另一方；任何仍有资格的一方必须补齐数据。两方结果完成后再按评分规则比较。
