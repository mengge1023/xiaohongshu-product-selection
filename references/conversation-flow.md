# 对话流程

## 状态

单品字段：`url, sales_total, cart_24h, benchmarks[], sale_price, purchase_price, shipping_cost, material_level`。每条 benchmark 包含 `followers, days_ago, likes, same_product`。

按字段顺序处理，但先吸收用户主动提供的所有明确值。一次只询问一个最靠前的缺失字段。模糊值必须确认；用户纠正时覆盖旧值并重新校验。

1. 问累计销量；>11000 立即换品。
2. 问 24h 加购；<200 立即换品。
3. 收集同款对标。单条对标的粉丝、发布时间、点赞、同款确认必须绑定；允许添加多条。若用户还未说明是否同款，单独确认。
4. 问售价、拿货价、运费，每次一个；调用利润脚本。
5. 问素材 A/B/C；不接受“挺多”等模糊描述。
6. 数据齐全后调用校验/评分脚本并报告。

## URL

不要仅凭域名猜产品页或笔记页。若 URL 路径特征或可见页面信息足以确认则分类；否则请用户明确类型。笔记 URL 的回复目标是取得对应商品链接。

## AB

维护 `product_a`、`product_b` 两套状态。默认完整处理 A 后再处理 B。某方硬淘汰即停止该方，继续另一方；任何仍有资格的一方必须补齐数据。两方结果完成后再按评分规则比较。
